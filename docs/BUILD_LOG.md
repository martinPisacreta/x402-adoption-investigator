happened is written here (SPEC.md section 14). The README section "AI coding tools: Claude Code and Cursor"
summarises this file, and `metadata.json` carries the same facts in machine-readable form.

All times are UTC. The build window opened on 2026-10-22 at 00:00 UTC; nothing written for this repository predates
it (file timestamps on the build machine: fixtures 00:02-00:08, SPEC.md 00:49, `.cursor/rules/project.mdc` 00:50,
`run.py` 01:13, builders and integration 01:30-03:20, README 02:53, review fixes from 03:30). Pre-existing
components, declared in the README: Automata and its x402 store `tienda.textokit.store` (built and operated by the
author, used only as a read-only data source; no code from it is in this tree), the upstream Meterless H-MEM
conformance vectors copied verbatim into `tests/vectors/`, the Zetaris platform run in Docker, and the Python
standard library.

## Day 1, review fixes (2026-10-22, 03:30-05:00 UTC): honesty pass after the first review

A review of the tree against the hackathon rules and `.cursor/rules/project.mdc` found two things that read as a
staged demo. Both were removed rather than explained away; everything that changed in the examples is listed here.

  was to be rejected by the Critic in example 02 so that `rejected_claims[]` would not be empty. Removing the
  seed memory did not change that rejection (the C4 scope rule in code did it), so the memory id was decoration.
  The metric and its reducer are gone; the C4 rule stays and is proven by `tests/test_critic.py` and by
  `tests/test_run_contract.py::test_a_rejected_claim_makes_the_status_partial`, which registers such a metric for
  the duration of one test and checks the rejection, the trail and the `partial` status. Example 02 is now `ok`.
- The "retry of the Writer" in every example was a deterministic second round produced by an index mismatch:
  `mem-seed-007` carried `source:receipts`, so the Critic's C3 gate demanded `basis_mismatch` on every receipts
  claim (including "77 settled sales in total", where it says nothing), while the Analyst only mapped the codes the
  registry listed. Fixes: the Analyst now applies the whole policy index (`investigator/agents/pitfalls.py`, shared
  with the Critic), `mem-seed-007` names the two metrics that actually compare Bazaar counters with receipts
  (`metric:bazaar_calls_30d_for_host`, `metric:external_sales_30d`; the index accepts `metric:` entities), the
  narrative pass B now reads the numbers printed inside text-valued claims (it used to flag "normativa-ar=2" and
  "saylorinnovations.com=1568" as unsourced and the Writer dropped those sentences silently; dropped sentences are
  now a `recovery{narrative_trimmed}` event), and the runner no longer logs a `retry` for a Writer revision
  (`retry` is reserved for real retries: the Fetcher's backoff). All three sample runs finish in one clean round.
- What memory does is now measured instead of claimed: `scripts/memory_ablation.py` runs example 01 with and
  without `mem-seed-003` and writes the diff to `examples/memory-ablation/summary.json` (one caveat lost on
  `settlements_verified`, fifteen citations lost, feedback entries lost, verdict unchanged).
- Tests caught one more thing while regenerating: `sql.jsonl` carried `file:///...Temp/...` URIs of the build
  machine; the SQLite view layer now writes `logs/<run_id>/exports/<file>` and the reproducibility test compares
  every committed side file byte for byte.
- Smaller fixes from the same review: `.env.example` no longer ships `SAMPLE_MODE=1` uncommented (copying it made
  a documented live run replay fixtures silently); the quick start prints the envelope (`--print-output`) and says
