## Day 1, review fixes (2026-10-22, 03:30-05:00 UTC): honesty pass after the first review

A review of the tree against the hackathon rules and `.cursor/rules/project.mdc` found two things that read as a
staged demo. Both were removed rather than explained away; everything that changed in the examples is listed here.

- Rule 2 ("never hardcode a demo answer") fired on `unique_payers_summed`: a registry metric whose only purpose
  was to be rejected by the Critic in example 02 so that `rejected_claims[]` would not be empty. Removing the
  seed memory did not change that rejection (the C4 scope rule in code did it), so the memory id was decoration.
  The metric and its reducer are gone; the C4 rule stays and is proven by `tests/test_critic.py` and by
  `tests/test_run_contract.py::test_a_rejected_claim_makes_the_status_partial`, which registers such a metric for
  the duration of one test and checks the rejection, the trail and the `partial` status. Example 02 is now `ok`.
- The "retry of the Writer" in every example was a deterministic second round produced by an index mismatch:
  `mem-seed-007` carried `source:receipts`, so the Critic's C3 gate demanded `basis_mismatch` on every receipts
  claim (including "77 settled sales in total", where it says nothing), while the Analyst only mapped the codes the
  registry listed. Fixes: the Analyst now applies the whole policy index (`investigator/agents/pitfalls.py`, shared
  with the Critic), `mem-seed-007` names the two metrics that actually compare Bazaar counters with receipts
  (`metric:bazaar_calls_30d_for_host`, `metric:external_sales_30d`; the index accepts `metric:` entities), the
  narrative pass B now reads the numbers printed inside text-valued claims (it used to flag "normativa-ar=2" and
  "saylorinnovations.com=1568" as unsourced and the Writer dropped those sentences silently; dropped sentences are
  now a `recovery{narrative_trimmed}` event), and the runner no longer logs a `retry` for a Writer revision
  (`retry` is reserved for real retries: the Fetcher's backoff). All three sample runs finish in one clean round.
- What memory does is now measured instead of claimed: `scripts/memory_ablation.py` runs example 01 with and
  without `mem-seed-003` and writes the diff to `examples/memory-ablation/summary.json` (one caveat lost on
  `settlements_verified`, fifteen citations lost, feedback entries lost, verdict unchanged).
- Tests caught one more thing while regenerating: `sql.jsonl` carried `file:///...Temp/...` URIs of the build
  machine; the SQLite view layer now writes `logs/<run_id>/exports/<file>` and the reproducibility test compares
  every committed side file byte for byte.
- Smaller fixes from the same review: `.env.example` no longer ships `SAMPLE_MODE=1` uncommented (copying it made
  a documented live run replay fixtures silently); the quick start prints the envelope (`--print-output`) and says
  that an ambient `OPENAI_API_KEY` / `ZETARIS_PASSWORD` switches `auto` to live; `--serve` binds `127.0.0.1`
  unless `--host` is given and refuses bodies over 1 MB; an export that cannot be written is an `E_INTERNAL` that
  names the path and its length (Windows `MAX_PATH`); `scripts/one_command.sh` uses `python3` when present; two
  `ResourceWarning`s in the tests (an unclosed `EventLog`, an unclosed socket) are closed.
- Not fixable from inside the tree and still open at review time: the repository had no commit and no public remote
  yet, and the "Cursor sessions" section was empty until the viewer session below. Both were resolved the same day:
  the initial commit 169e896 is on the public remote github.com/martinPisacreta/x402-adoption-investigator, and
  the section lists two Cursor Agent sessions.

## Day 1, pre-submission verification fixes (2026-10-22, 16:00-17:00 UTC)

An independent verification pass from fresh clones found mechanical defects; all are fixed in the commits after
e654f59:

- Line endings. No `.gitattributes`, and `Path.write_text` wrote CRLF on Windows. A default Windows clone failed 4
  of 193 tests (sha256 of fixtures and SQL converted to CRLF, byte-identical examples), an LF clone failed 1 (fresh
  `output.json` with CRLF), and Linux/Docker failed 1, because the `exports_sha256` recorded in
  `fixtures/zetaris/q*.json` were the CRLF variants. Fix: `.gitattributes` (`* text=auto eol=lf`, captured
  fixtures and upstream vectors `-text`, media binary), `newline="\n"` on every writer, and `exports_sha256`
  re-hashed over the LF exports. All 228 old values equal the sha256 of the same single-line exports ending in
  CRLF and are kept as `exports_sha256_recorded_crlf` (see `fixtures/zetaris/README.md`). Rows, headers, params
  and `sql_sha256` are unchanged, and no committed example output changed.
- Wrong GitHub owner in the README clone command, `REPO_URL` and the five schema `$id` values (404); now
  `martinPisacreta`.
- Absolute local paths in the three live traces (`fetch.jsonl` `export_path` / `raw_path`) rewritten to
  `logs/<run_id>/...`. The collector now writes that form for run folders outside the repository too, and
  `traceback.txt` replaces the repo root and home directory.
- Smaller items: sample mode honours `LOG_DIR` (README and `--help` said so); the README's Windows `MAX_PATH` bound is
  the measured one (repo path up to 143 characters, logs dir up to 148, checked at 148/149); `--serve` returns 400
  for a body that is not JSON and 422 for a schema-invalid one, now documented and tested; a tautological test
  assertion became a real one; `.gitignore` / `.dockerignore` cover `.env.*`, key, certificate, wallet and cookie
  files; World Model provenance no longer doubles `fixtures/raw/`.
- Verified: `python -m unittest discover -s tests` = 199 tests OK in a default Windows clone, an
  `autocrlf=false` clone and the Docker image built from it (`--network none`). Every example input ran with
  `--sample` (exit 0) and rewrote the committed example files byte for byte, and `scripts/one_command.sh` passed
  in the image.
